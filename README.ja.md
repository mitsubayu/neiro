# neiro

*[English](README.md)*

Apple Music を**曲ごとのネイティブレートのまま再生**し、パラメトリック EQ を
かける macOS メニューバー常駐アプリです。

Music.app は出力デバイスに設定されたレートへすべてリサンプルしてしまうため、
96 kHz のマスターも DAC が 48 kHz なら 48 kHz で届きます。neiro は Core Audio の
プロセスタップで Music の音声を受け取り、その曲の本来のレートを読み取って、
エンジンと DAC をそのレートで組み直してから、選んだ出力デバイスへ再生します。

レート変更は**曲の頭でだけ**行います。短い無音の後、頭から正しいレートで鳴ります。
曲の途中で切ることはありません(次の曲のための変更は曲の境界まで待ちます)。

> 開発は Azure DevOps 上のプライベートリポジトリで行っていて、この GitHub
> リポジトリは公開用のミラーです(公開する価値があるときに更新します)。Issue は
> 見ています。Pull Request は手作業で上流へ取り込む形になるため、大きめの変更は
> 先に Issue で相談してもらえると助かります。

## できること

- 曲ごとのソースレート追従(44.1 / 48 / 96 kHz など)
- 10 バンドのパラメトリック EQ(RBJ biquad)。応答カーブは直接ドラッグでき、
  背景にリアルタイムのスペクトラムが出ます
- プリセット。出力デバイスに紐付けておくと、そのデバイスに切り替わった時点で
  自動適用されます(ヘッドホンとスピーカーで補正を変えたいとき用)
- 即座に A/B できるバイパス、Undo/Redo、パネルを開いたままにするピン
- メニューバーに曲名・コーデック・**実際に再生しているレート**を表示

macOS 15 以降と Music.app が必要です。Apple Silicon / Intel 両対応。

## できること・できないこと

| | |
| --- | --- |
| 曲ごとのソースレート追従 | 対応(44.1 / 48 / 96 kHz。DAC 側が報告する実レートで確認済み) |
| ギャップレスなレート切り替え | **非対応。** 一時停止 → エンジン再構築 → 0:00 から再開という手順のため、レートが変わる曲では**冒頭に約2.4秒の無音**が入ります |
| ビットパーフェクト | **非対応。** プロセスタップが渡してくるのは 32bit float で、EQ も float で処理します。あくまで「レートを合わせる」ものです |
| オーディオドライバ | 不要(プロセスタップだけで完結) |
| EQ | 10 バンドのパラメトリック EQ、カーブは直接ドラッグ可。プリセットは出力デバイスに紐付け可能 |
| ヘッドホン別プロファイル集 / プロファイルの入出力 / A/B レベルマッチング | 未実装 |

## インストール

[Releases](../../releases) から zip をダウンロードして展開し、`neiro.app` を
`/アプリケーション` に移動してください。

配布ビルドは ad-hoc 署名のみで公証(notarization)を受けていないため、初回起動は
macOS にブロックされます。**システム設定 → プライバシーとセキュリティ** を開き、
セキュリティの項目まで下がって、neiro についてのメッセージの横にある
**このまま開く** を押してください。

初回起動時に2つの許可を求められます。

| 許可 | 用途 |
| --- | --- |
| 画面とシステムオーディオの録音 | プロセスタップが Music の音声を読むために必要です。Music 以外の音は取得せず、ディスクへの記録も一切しません。 |
| オートメーション → Music | レート切り替えの前後で Music を一時停止・再開し、音の途中で切り替わらないようにするために使います。 |

ad-hoc 署名は**ビルドごとに署名が変わる**ため、アップデートのたびに録音の許可を
求め直されます。

## ビルド

```bash
brew install xcodegen
scripts/ci.sh          # プロジェクト生成 → テスト → Release ビルド
open build/Build/Products/Release/neiro.app
```

`neiro.xcodeproj` は `project.yml` から生成するのでコミットされていません
(ソースファイルを追加したら `scripts/bootstrap.sh`)。署名はキーチェーンにある
Apple Development 証明書を自動で使います(`DEVELOPMENT_TEAM=…` で上書き可能)。
証明書が無い環境では未署名でビルドされます。

**普段の利用は必ず Release ビルド**で。Debug は最適化なしの DSP がリアルタイム
スレッドで回るため CPU を 37% ほど食います。

## 仕組み

| | |
| --- | --- |
| キャプチャ | Music のオーディオプロセスに対する `CATapDescription(stereoMixdownOfProcesses:)`。元の出力は OS 側でミュートされるので二重に聞こえません |
| 再生 | タップと出力デバイスを1つのプライベート集約デバイスにまとめ、ドリフト補正は HAL に任せます |
| DSP | HAL のリアルタイムスレッド上でカスケード接続した RBJ biquad。係数の差し替えはロックフリー |
| レート検出 | Music はソースレートを API で公開していないため、統合ログのデコーダ行を読み取ります |

設計とレート切り替えの判断ルールは [SPEC.md](SPEC.md)、実装中に踏んだ地雷
(Core Audio の再起動ループ、AppleScript の永久ブロック、メニューバーの制約)は
[KNOWLEDGE.md](KNOWLEDGE.md) にまとめてあります。

## 作った理由

同じことを商用で、しかもよくできた形で実現しているものに
[MusEQ](https://museq-app.com) があります。neiro はその発想を、仕組みを理解する
ために一から作り直したものです。名前は音色から取りました。
